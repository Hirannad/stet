# Validation

Two rounds so far, both before the plugin was published. Round 1 asked whether the tool's edits
survive a native ear. Round 2 asked a question round 1 could not: how often the machinery fires at
all, on text that is actually machine-written.

They are recorded in the order they ran, and **round 1's findings are left as they were written** —
including the ones this repository has since acted on. A validation record that gets edited to
match the current code is not a record. What changed afterwards is in its own section.

---

## Round 1 — 2026-08-13

The first behavioural measurement of `stet-hungarian`. Real Hungarian texts, every proposed change
labelled by a human, with one addition: the labelling was a **single-blind A/B ballot**, so the
rater did not know which variant the tool had produced.

The headline is not what the catalogue's own risk model predicted.

### Method

Five Hungarian texts were run through the full workflow (Pass −1 … Pass 6), register pinned to
`neutral`, always in review mode, never at a file. Each run happened in an isolated agent context
that wrote its three-part output to a file; the change table and the pattern IDs were withheld from
the rater until the ballot closed.

Ballot items came in four classes:

| class | what it contrasts | what it measures |
| --- | --- | --- |
| `live` | a change the tool actually made vs. the original | does the pattern survive a native ear |
| `suppressed` | an edit the tool **declined** (from its own suspect list) vs. the original | is the brake too tight |
| `decoy` | a deliberate hypercorrection drawn from the `HU-B` do-not-touch list | catch trial |
| `retest` | an earlier item re-shown with A/B swapped | within-session consistency |
| `repair-choice` | two valid repairs of one real error, against each other | which repair a reader prefers |

`repair-choice` was added mid-round, when a text turned out to contain an actual error with two
defensible fixes — a question neither `live` nor `suppressed` asks. No `retest` item survived to a
verdict; see "Two defects in this round's own instrument".

Construction rules: the unchanged context was rendered once above both variants as a byte-identical
slice; variant text was exactly what the run emitted, with no ballot-time polishing; the A/B order
was drawn at run time into a key file the rater never saw; every item used an identical question
string and options labelled only `A`/`B`; after each batch the rater flagged which decisions were
uncertain, and an uncertain item was barred from producing any catalogue change.

**Typographic and orthographic `FIX` patterns were excluded from the ballot.** They are norm
questions settled by *A magyar helyesírás szabályai*, not matters of preference — as
[`references/sources.md`](../skills/stet-hungarian/references/sources.md) says itself — and only one
variant can carry `„…”`, which labels the item. They were verified mechanically instead.

### Material

The corpus was one company's marketing-strategy playbook: 25 sections, 10 485 words of Hungarian.
Surveying it first changed the plan. Every one of `-ásra/-ésre kerül`, `történik`, `valósul meg`,
`lehetővé teszi`, `kulcsfontosságú`, `Fontos megjegyezni`, `nem csupán`, `amennyiben`,
`vonatkozásában` and `Ön` returned **zero** hits. The shipped text is not machine-ish Hungarian, so
it served as the negative fixture; the machine-origin material came from unaccepted AI-generated
section proposals the rater had never read, which also removed the largest blinding leak.

Five texts, ~2 400 words, by provenance:

| text | provenance | FIX | SOFT | suspect list |
| --- | --- | --- | --- | --- |
| section proposal, 438 w | AI-generated, never read by the rater | 2 | **1** | 18 |
| hand-merged draft, 632 w | operator | 1 | 2 | 28 |
| edited human text, 517 w | human + operator | 9 | **0** | 21 |
| `llm` section, v1, 359 w | pure machine output, never hand-edited | 16 | **0** | 15 |
| `user-edit` section, v7, 456 w | negative fixture | 8 | **0** | 19 |

**36 `FIX` changes and 3 `SOFT` changes in total**, against 101 suspect-list entries. On the purest
machine specimen in the corpus — generated by an LLM and untouched by a human since — the tool made
zero `SOFT` changes and only typographic ones. The translationese and LLM-rhetoric passes did not
fire on pure LLM output.

### Results

20 ballot items, in two batches of ten. One was invalid by construction (see below); four were
flagged uncertain and produce no verdict. Of the 15 confident decisions:

| class | confident result |
| --- | --- |
| `live` — changes the tool made | **0 of 2 survived** |
| `suppressed` — edits it declined | **8 of 9 were wanted** |
| `decoy` — hypercorrections | **0 of 3 got through** |
| `repair-choice` — two valid repairs of one error | the tool's choice won |

By blocking reason, confident decisions only: `uncertainty` 3/3 went to the edit,
`cluster override did not fire` 2/2, `cluster threshold` 1/1, `valency guard (HU-H08)` 1/1,
`no pattern exists` 1/1 — and **`register gate` 0/1**. One brake proved calibrated: the register
gate.

So the picture inverts the documented risk model. The catalogue's stated primary failure mode is
over-correction. On this corpus the tool errs the other way: its **do-not-touch list is sound**, its
**`FIX` layer is sound**, and its **`SOFT` layer is miscalibrated in both directions** — it fired on
things a native reader rejected, and declined things a native reader wanted.

The four uncertain items are themselves informative. By operation they were three:
`megkönnyíti`/`teszi könnyebbé`, nominalisation → verb (twice), and `rendelkezik` → `van` —
precisely the `SOFT` layer's core operations. If a native ear cannot confidently tell the two variants apart, the
claim that the operation removes a machine tell is weak.

Length did not drive the choices in the first batch (the shorter variant won 4 of 10). The second
batch's items were 7-of-10 shortening, which is a property of the item set and could not be fixed
by shuffling; it is recorded as a confound.

### Findings, and what changed in the catalogue

**1. `HU-T01` contradicted itself, and this caused a real regression.** The pattern's prose says the
Hungarian closing mark is the upper one, but the glyph it *printed* was U+0022. Its `Jelek:` line
listed the same character three times. Its `JÓ:` example was `„a bevezetés csúszik"` — the pattern's
own correct example was wrong — and its `Mikor NE` named that wrong form as the correct one. Across
the whole skill there were **69 occurrences of `„…"` and zero of `„…”`**. A model matching the
printed example emits half-fixed output, which is exactly what one run did on its first pass.
During this round the defect reproduced on live output: two straight closing quotes went into text
about to be published and `HU-T01` did not catch them.
*Fixed:* all 69 closing marks corrected across 12 files, and the three degenerate signs lists
rewritten to distinguish straight from English-typographic quotes. `scripts/check.py` stays green.

**2. The "not evidence" rule's list does not match what actually blocks hits.** `SKILL.md` names
four voiding reasons (register gate, untouchable zone, `[jelöld]`, uncertainty). Across four runs the
real blockers were mostly elsewhere: a pattern's own `Mikor NE` clause (10 of 19 suspects in one
run), the "megőrizendő jegyek" list in `06-rhythm.md`, "no pattern exists", a pattern's own internal
cap, the budget, and the cluster threshold. In one run the four named reasons covered 5 of 15
suspects. The rule's own stated rationale covers all of them; its enumeration does not.
*Open.*

**3. The cluster machinery was outcome-deciding once in five runs, and unmeasurable in the other
four.** On the AI-generated proposal, a budget-blocked `HU-F01` kept its 2 points, which pushed the
paragraph to the threshold and licensed the run's only `SOFT` edit — and the ballot independently
rejected that edit. On the other four texts the two readings produced identical change sets, because
every `SOFT` candidate was stopped earlier by its own `Mikor NE`. The cluster and budget system, the
catalogue's most novel component, **did not bind in four of five runs.**
*Open.* This round cannot calibrate it.

**4. Tables are undefined as a paragraph unit.** `SKILL.md` defines a paragraph as a prose paragraph
or a whole list, and says nothing about tables. Roughly a fifth of the corpus was tables, where the
cluster gate and the two-`SOFT`-per-paragraph budget therefore have no defined scope.
*Open.*

**5. A class of ordinary orthographic error is unreachable.** Three real errors in the corpus matched
no pattern: a missing consonant doubling, a compound written as two words, and a wrongly hyphenated
compound. The first was the text's one indisputable error. The catalogue is **provenance-shaped** —
it hunts machine tells — so it systematically misses ordinary human typos.
*Open, and arguably out of scope by design; recorded so the scope is a decision rather than a gap.*

**6. The language gate held on a genuinely mixed text.** Two fully English quotations inside
Hungarian prose came back byte-identical, while the Hungarian sentence beside them was corrected.
An English **heading** among Hungarian headings, however, falls within no pattern's scope.
*Open.*

**7. The register checklist conflicts with itself.** `SKILL.md` files `marketing` under `informal`;
`registers.md` files `dokumentáció` under `neutral`. A marketing-strategy document matches both on
different axes. It resolves via "the channel decides" plus the conservative tie-break, but only for a
reader who reaches those lines.
*Open.*

**8. File mode leaves a wrong intermediate version on disk.** In file mode the skill wrote twice: the
first write introduced a straight closing quote, the Pass 6 re-check caught it, and the second write
fixed it. Pass 6 earns its place, but an interruption between the two writes leaves a corrupted file.
Review mode has no such window — and it held, by instruction-following rather than by mechanism:
at the time of this round there was no `allowed-tools` declaration, and Write was available
throughout. One was added afterwards; round 2 measured it and found it changes nothing. See
"What changed after round 1".
*Open; a known backlog item at the time, now confirmed empirically. Round 2 took this further —
see "What changed after round 1".*

**9. `HU-F01`'s terminus test is close to unfalsifiable.** "Used outside the text in the profession"
is true of nearly every non-coined `-ás/-és` noun, so the catalogue's largest pattern can in practice
only fire on coinages — which `HU-R09` already owns.
*Open.*

### Two defects in this round's own instrument

**The round-1 key was published too early.** The results table, with pattern names and choices, went
out before retests were collected, so those items are retroactively unblinded and the test–retest
measurement for round 1 is lost. Rule adopted: no key is published until that round's retests are in.

**One decoy was invalid.** A terminus-synonymisation catch trial also differed in lexical quality —
the rater judged the substituted word simply better in context — so the item measured word choice
rather than the forbidden operation. Rule adopted: **a decoy may differ from the original only in the
forbidden operation, never in lexical quality.**

### Limitations of this round

One rater judged this round: the author of the skill, who also wrote or approved much of the text it
was run on. Ratings were single-blind — the rater did not know which variant came from the tool; the
operator did. For the shipped-text items the rater had read the material before, so recognition of
the original cannot be ruled out; the machine-origin items had never been read. The material is one
document: roughly 10 500 words of Hungarian marketing-strategy prose in one register (`neutral`),
from one company, part of which the tool had already processed in earlier rounds. 15 items reached a
verdict, covering about 14 of the catalogue's 118 patterns; most patterns were never exercised, and
no pattern was judged more than twice. This round therefore reports **counts, not rates**. It does
not establish the tool's precision, its over-correction rate, its false-positive rate on clean
Hungarian, or any per-pattern accuracy, and none of its numbers generalise to other genres,
registers, or raters. Typographic and orthographic `FIX` patterns were checked against *A magyar
helyesírás szabályai* rather than balloted, because they are norm questions and not matters of
preference. **No pattern's estimate marker (`?`) was removed on the strength of this round**: a round
like this can retire a pattern or add an exception; it cannot turn an estimate into a measurement.
There is **no second rater**, by the owner's decision, so every judgement below rests on one
interested reader and should be read as a hypothesis a second reader may overturn. Disagreement is
welcome as an issue.

### What this round did not do

It did not calibrate the cluster threshold or the budget (finding 3 explains why it could not), it
did not exercise the `legal` or `informal` register profiles, it did not test the eight precedence
pairs or the four cluster overrides on seeded inputs, and it did not test the `[jelöld]` behaviour
against a text that actually contains those patterns — none of the five texts did.

### What changed after round 1

Between the two rounds the catalogue changed in five ways, all of them narrowing what it claims
rather than what it does. Recorded here so the round 2 numbers are attributable to a stated
configuration.

**1. `measured_patterns` is now empty, and every soft pattern is estimate-marked.** Three patterns —
`HU-L01`, `HU-L06`, `HU-L11` — previously stood without the marker on the strength of a single
source: a Hungarian AI-text detector named in `sources.md` with no URL, edition, page or method
description. The eight lexical tells it reportedly names are consistent with the rest of the
catalogue, so they stay on the `Jelek` lines; the *unmarked evidence value* did not, because it
rested on something no reader can check. The catalogue's own first rule is that a model reads an
unmarked value as measured fact and edits with unearned confidence.

Consequence, and it is a behavioural one: no soft pattern can now justify an edit through the
cluster score alone.

**2. `HU-L06` became a cluster override, so the marker change would not silently disarm it.** The
`nem csupán X, hanem Y is` frame is the strongest English-import structure in Hungarian and it is
`[kern]`-stable — it rests on syntax, not on a word list with an expiry date. Its override carries a
two-gate falsifiable test: two or more frames in one paragraph, **and** at least one of them failing
the straw-man test. `HU-L01` and `HU-L11` are lexical lists and stayed cluster-bound. Overrides went
from four to five.

**3. Tables are now defined as a paragraph unit — by exclusion.** Round 1 finding 4. Soft patterns
do not fire inside a table, at any granularity; fix-class patterns do, because a wrong quotation
mark is wrong in a cell too. The cluster gate wants co-occurring signals in a paragraph and the
budget counts sentences; neither is meaningful in a cell, and forcing it makes the gate open or shut
arbitrarily.

**4. The "what you cannot act on is not evidence" rule became a principle instead of a list.** Round
1 finding 2 showed the four enumerated blocking reasons covered 5 of 15 suspects in one run, because
the real blockers were mostly each pattern's own exception clause. The rule now names the reasons it
knows about and says explicitly that any block counts.

**5. The register checklist's tie-break moved to where the tables are.** Round 1 finding 7: a
marketing-strategy document matches `informal` by topic and `neutral` by genre. The resolution — the
channel decides, and failing that the stricter profile wins — existed, but three files away from the
reader who needed it.

Also fixed: the `HU-L01` header printed in `SKILL.md`'s own notation example still showed the
pre-change form. That is the `HU-T01` defect shape exactly — a printed example contradicting the
catalogue — so it is now the kind of thing `scripts/check.py` gates rather than the kind a reader
finds.

**What did not change: the soft layer's operations.** Round 1 rejected them on one rater's blind
judgement, which the round itself calls a hypothesis. Redesigning the layer on that evidence would
repeat the error the catalogue is built to avoid. It stays, documented as the weak part, until a
round with a second rater and seeded inputs says what to do with it.

## Round 2 — 2026-08-14

Round 1 asked whether the tool's edits survive a native ear. It could not ask the prior question:
**how often does the machinery fire at all, on text that is actually machine-written?** Its corpus
was one company's confidential playbook, largely hand-edited, in one register — and its numbers had
to be taken on trust, because the corpus could not be published.

Round 2 answers that question on a corpus that ships with this repository. Nine Hungarian texts,
3 610 words, generated by three Claude model families on three topics chosen to span three register
profiles, each run twice: **eighteen runs.** The specimens, the generation prompt and every count
are in [`../tests/corpus/`](../tests/corpus/). Anyone can re-run it and disagree with the numbers.

There is no rater and no ballot in this round. That is deliberate — round 1's binding limitation was
its single interested rater, and adding more of the same evidence would not have fixed it. This
round measures **firing**, not correctness. A `SOFT` edit that fires here may still be a bad edit;
round 1 suggests it probably is.

### Method

The generation prompt was byte-identical across the three models and mentions nothing about style,
machine tells, or wanting natural Hungarian — a specimen generated under instructions to sound human
would measure the instructions. Each model produced its three texts in one fresh agent context.

Every specimen was then run through the full workflow (Pass −1 … Pass 6) in an isolated agent
context, in review mode, never at a file, with the register **pinned by the operator before the
run** rather than inferred by the skill. The measuring agent was the same model for all eighteen
runs, held constant so that only the specimen's origin varies.

Specimens run 348–443 words. The length band is load-bearing: the text-level edit budget only
engages above five sentences, and the cluster gate needs a paragraph with room for several
co-occurring signals. A 300-character specimen would have measured nothing about the soft layer,
which is the layer under test.

### Results

| model | FIX | SOFT | suspect list |
|---|---|---|---|
| Claude Haiku 4.5 | 64 | **18** | 138 |
| Claude Sonnet 5 | 26 | **0** | 67 |
| Claude Opus 5 | 47 | **0** | 57 |

Per-specimen counts, both runs, in [`../tests/corpus/results.md`](../tests/corpus/results.md).

**Twelve runs on Sonnet- and Opus-generated Hungarian produced zero `SOFT` edits.** Not few —
none. All eighteen `SOFT` edits came from Haiku, and from only two of its three specimens. The
result replicates: each specimen was run twice, and the sign never flipped in either direction.

The `FIX` layer, by contrast, fires everywhere: 137 changes across the eighteen runs, on every
specimen from every model. So does the suspect list: 262 entries, meaning the tool consistently
*notices* things it then declines to act on.

### What this changes

**1. The soft layer is not dead — it is calibrated to a machine-ishness the stronger models no
longer produce.** Round 1 saw zero `SOFT` edits on its one pure-machine specimen and could not tell
whether the layer was inert or the specimen was clean. Eighteen runs across three model families
separate those: the layer fires, reliably, on Haiku's Hungarian, and never on Sonnet's or Opus's.

The practical reading for anyone installing this: on output from a frontier model, expect the
typographic and orthographic layer to do the work and the soft layer to stay quiet. On output from a
smaller or faster model, expect the soft layer to engage.

The uncomfortable reading: a catalogue of LLM tells is a **moving target**, and the lexical lists
carry a review date for exactly this reason. Some of what this catalogue calls a machine tell is
better described as a tell of a *2025-era* machine.

**2. The register gate is not the driver, and it held.** `informal` enables every pass at full
strength and produced zero `SOFT` edits across six runs; `formal` switches Pass 5 off except for
three content patterns and produced twelve. The difference tracks the specimen, not the profile.
Separately, `HU-L07` — which the pass matrix forbids in `formal` — appears in all three `formal`
runs' output and in every case sits in the register declaration or the suspect list, never in a
change table. No violation. Round 1's finding that the register gate is the one calibrated brake
survives.

**3. `allowed-tools` is not a mechanism.** Between the rounds, the review-only rule was moved out of
prose and into the frontmatter as `allowed-tools: Read, Grep, Glob`, on the principle that a
constraint belongs in a field rather than a paragraph. Round 2 measured it. A probe wrote a file
with `Write`, invoked the skill, and wrote another — both succeeded; `Edit` on a missing path
returned "file does not exist" rather than a permission refusal, so dispatch was normal; the tool
set did not narrow. All eighteen measuring agents independently reported write tools available.

So the declaration states an intent that nothing enforces, and for roughly an hour this repository's
README claimed the skill "cannot overwrite your text even if asked to." That was false, and it was
*worse* than the prose it replaced, which at least claimed nothing. Both texts now say what is true.
The field stays — it is the correct declaration, and a future runtime may honour it — but it is
labelled as intent, not as a sandbox.

The general lesson is not about this field: **a native mechanism is not a mechanism until you have
measured it.**

**4. The three-part output has no machine-readable shape.** `SKILL.md` specifies corrected text,
change table, suspect list — and fixes neither the heading strings, nor the heading levels, nor the
table columns, nor whether a "reviewed and came out clean" subsection may sit inside the change
table. Across eighteen runs the shape varied enough that a line-range parser could not reliably tell
a change row from a suspect entry: one run's change table was two lines, another's fifteen with a
nested subsection. This blocks automated regression testing against `tests/fixtures/`, which is the
one thing that would make those fixtures more than specifications. *Open.*

**5. Run-to-run variance is real and asymmetric.** `FIX` counts moved by 0–4 between the two runs of
a specimen. The suspect list moved much more — 149 entries in the first pass against 113 in the
second, a 24 % drop with no change to the inputs or the catalogue. `SOFT` counts kept their sign but
not their magnitude (4 → 2 on one specimen, 6 → 6 on another). Two runs is enough to see that the
headline result is stable and that the counts are not; it is not enough to quantify either. Nothing
in this repository should be read as precise to ±1.

### Limitations of this round

No rater, so nothing here speaks to whether any edit was *good* — only to whether it happened. The
specimens came from Claude Code agents rather than bare model endpoints, so this measures "how a
Claude Code user gets Hungarian", and the absolute numbers carry that caveat; the cross-model
comparison holds because all three were generated the same way. One generation run per model and one
prompt per topic, so nothing separates model behaviour from sampling variance in the specimens
themselves. Two measurement runs per specimen, which detects gross instability and estimates
nothing. Three topics and three registers: no `legal` profile, no fiction, no academic prose, no
genuinely translated source. The measuring agent was a single model, held constant — a different one
might fire differently, and that is unmeasured. Three model families is not "language models"; it is
three members of one vendor's family at one point in time. And the `[jelöld]` behaviour is still
untested, because none of these nine specimens contains those patterns either.

**No pattern's estimate marker was removed on the strength of this round**, and `measured_patterns`
stays empty. A firing-rate measurement is not evidence that a pattern's `AI:` value is right.

### What comes next

Round 3 needs the thing neither round could supply: **a second rater**, plus seeded inputs to
calibrate the cluster gate and the budget, and a text that actually contains the `[jelöld]`
patterns. It also now has eighteen `SOFT` edits on record, all from one model family, which is the
first concrete material a ballot could be run on — but running that ballot with one interested rater
would only repeat round 1's binding limitation.
